감지한 Mac 기준 후보

MEASURE ON THIS MAC

원본 앱 수식으로 계산한 후보입니다. 이 칩·코어 조합은 우리가 실측 검증하기 전이며, 이 Mac에서 직접 측정해 채택합니다. 과거 독립 수용 시험 범위는 M4 Pro 20 GPU 코어의 현재값 시험이며, 모든 후보의 안정성·성능 향상을 보장하지 않습니다. M5의 비기본 workers도 미검증입니다.

확인된 규칙 + 투명한 독립 구현

짧은/긴 입력 각각 3회의 metrics decode 속도 upper median을 구해 평균을 냅니다. 측정 기준보다 엄격히 3% 초과 개선된 후보만 성능 개선으로 채택합니다. 속도 측정 temperature 0.6, 출력 256토큰. 긴 filler 입력값 32,000과 prefill 진단 8,000은 nominal 값으로 실제 tokenizer 토큰 수가 아닙니다. 후보 탐색 순서·복구 정책은 독립 구현이며 원본 전체와 같다는 보장은 없습니다.

별도 greedy 요청(temperature 0, seed 0, 최대 96토큰)의 message JSON 해시를 측정 기준과 비교합니다. seed 지원이나 정답의 의미적 정확성까지 보장하지는 않습니다. 측정 중 SSD 캐시를 끄고 외부 CLI 요청을 거부합니다. 긴 입력을 위해 문맥을 최소 65,536으로 임시 확장한 동일 조건에서 후보를 비교하고 복원합니다. 답변 내용은 저장하지 않습니다.

worker와 chunk는 다른 지표로 선택합니다

감지 기반 worker 후보를 위의 decode 점수로 비교합니다. 선택한 worker에서 고정 chunk 후보 1024/2048/4096을 별도로 비교하며, 매번 새 UUID를 쓴 nominal 8,000 입력을 3회 측정합니다. chunk 점수는 실제 prefilled_tokens / prefill_seconds의 upper median입니다. 각 단계별 측정 기준 대비 엄격한 3% 초과 개선만 성능 후보로 선택합니다.

서버의 기준 응답·최종 조합 검증 지원 여부를 확인합니다.

문맥은 유지 · 캐시 용량은 디스크 기준 자동 선택

전체 자동 튜닝 성공 시 문맥과 캐시 사용 여부를 유지한 제안을 만들고 원래 설정·실행 상태를 복원합니다. 새 적용 흐름은 서버가 지원할 때 사용자 확인 후 저장·재시작합니다(구버전 서버는 성공 시 자동 적용). 현재값만 측정할 때는 용량도 바꾸지 않습니다. 문맥 선택지 32K·64K·128K·256K는 수동 설정용이며, 최적 문맥 자동 탐색은 확인되지 않아 수행하지 않습니다.

캐시 선택지는 8·16·32·64·128·192·256·384·512 GiB입니다. 여유 디스크의 20% 이하인 가장 큰 선택지를 고르며, 해당 선택지가 없으면 확인된 규칙대로 최소 8 GiB를 선택합니다. 이는 저장 상한으로 즉시 공간을 예약하지 않으며, 디스크 여유 공간을 보장하지 않습니다.
